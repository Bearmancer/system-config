# Music search — research depth, not a lookup order

A single source hit is not an answer. "Find every recording of work X" or "what's the duration of Y" is a research task: identify candidates, trace each one to its underlying original session, cross-check from a second angle, and only then call it complete. The failure mode this file exists to prevent: one query, one source, one result, reported as if it were exhaustive — when a second angle or a deeper page would have surfaced the session, pressing, or repress that got missed.

## Banned sources — streaming services

Never cite a streaming service as a source for metadata, credits, dates, or catalog facts — at any depth, not just the first hit. They're playback platforms, not discographic authorities: metadata is licensor-supplied, inconsistently normalized, and not independently verifiable. Banned: Spotify, Apple Music, Apple Classical, Amazon Music, Tidal, Deezer, Qobuz (its hi-res/classical-leaning catalog included).

A streaming service link is fine to hand the user as a listen-to pointer. It is never a citation for a fact, at any stage of the research.

## Method: entry point → trace → verify

Treat every source below as a place to find *candidates*, not a place to find *the answer*. Each candidate needs tracing before it counts.

### 1. Entry points — cast the net

Start with **MusicBrainz** (open metadata database — structured, MBID-citable, cross-referenced release/recording/work relationships) and **Discogs** (discography and pressing-variant detail, marketplace-verified catalog numbers). Query from more than one angle before treating the result set as complete:

- Composer/work + performer or conductor
- Performer/conductor + label
- Catalog number, if one is already known
- Work title alone, filtered by era/orchestra, to catch entries the first query's phrasing missed

A single angle finds a subset. Different angles surface different pressings, reissues, and box-set appearances of the same underlying session — run at least two before concluding a list is complete.

### 2. Trace each candidate to its underlying session

A catalog entry is not automatically a distinct recording. Reissues, box-set compilations, and streaming-era repackagings routinely repress an existing session under a new catalog number, new cover art, or a new decade's remastering. For every candidate:

- Identify the original recording session (venue, dates if known, orchestra) — not just the release date on the sleeve.
- Check whether it's a **repress** of an already-identified session (same take, new packaging) rather than an independent recording. State this explicitly: "all other listings are represses of [session]" is a real, useful finding — not a shortcut past the research.
- Where MusicBrainz/Discogs disagree or are thin on a given release, use **Presto Classical** (classical-specific retailer, strong on new-release and label-crossover detail) to fill the gap, then the **label's own website** last — authoritative for its own catalog, but slower to update and less cross-referenced than the aggregators, so it's the tie-breaker, not the starting point.

### 3. Verify before reporting complete

- If sources conflict on a date, catalog number, or session detail, state the conflict in one line rather than silently picking one.
- Before saying "N recordings exist," confirm each of the N traces to a genuinely distinct session — not N catalog numbers pointing at 2 sessions.
- A result set that stopped after one query, one source, or one page is not verified as complete — say so if that's as far as the research went, rather than presenting a partial list as exhaustive.

## Duration verification

A duration is a claim, not a lookup — the same one-source-and-stop failure applies here. Full worked rules (two-source citation, movement-breakdown cross-check, complete-vs-cut flagging, range-not-average for differing recordings): `deep-cut-classical` skill's "Timing verification" section — that discipline applies to any composer or work, including ones banned from *recommendation* there, since the ban list gates picks, not verification method reuse.
